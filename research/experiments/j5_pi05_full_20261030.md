# J5-ACT：RAW视觉编码器接入π0.5全量动作微调

## 授权与范围

用户确认J5视觉效果后，已在12818更新完整保存/native0停止；原视觉训练保持停止，保存目录不改动。本轮另开 `lzh/j5-pi05-full-finetune`，将该EMA编码器接入π0.5，训练视觉、连接层、语言骨干与动作专家全部参数。先沿用已有LIBERO的1421/177/173训练/验证/测试源分区和五照明；不接真实机器人，不把RoboTwin不同动作坐标的数据直接混入LIBERO动作头。

训练只输入RawVLA-Bench三通道pseudo-RAW与任务文本，以原始动作标注监督；没有RGB教师、RGB重建或视觉蒸馏目标。原J5学习没有RGB监督，但整个动作模型使用公开π0.5-base初始化，不能宣称整个VLA从零RAW预训练。

## 官方依据与实际适配

固定 [openpi 15a9616](https://github.com/Physical-Intelligence/openpi/tree/15a9616a00943ada6c20a0f158e3adb39df2ccac)，具体配方见 `third_party/openpi/src/openpi/training/config.py` 的 `pi05_libero`，动作目标直接继承 `PI0Pytorch.forward`。服务器另存该版本源码，不覆盖历史环境；原仓库模型/损失文件未修改。

官方SigLIP换成J5 `RAWEncoder`，新建384→2048投影，其余从官方π0.5-base权重初始化。实际可训练参数 **2,961,605,027**；去掉动作路径不用的语言生成头。没有冻结后端，也没有LoRA。J5原12818编码器来自远端 `outputs/j5-raw-relations-20261030/attempts/user-stop-12818/encoder.pt`。

| 项目 | 本轮设置 |
|---|---|
| 动作损失 | 官方Gaussian noise、Beta(1.5,1)时间采样、velocity=noise-actions、完整32维MSE |
| 动作序列 | horizon10，真实7维，其余补零；末帧重复填满序列 |
| 归一化 | 官方LIBERO q01/q99，保留越界值，不加额外delta动作变换 |
| 有效batch | 256；2卡×micro8×累积16 |
| 优化器 | AdamW，β=(0.9,0.95)，eps=1e-8，wd=1e-10，官方梯度clip1 |
| 学习率 | 10k warmup至5e-5，后续保持5e-5；采用官方warmup起点 |
| EMA/更新 | EMA0.999；30,000更新 |
| 采样 | 官方10步Euler flow积分；闭环每次执行前5步再观测 |

这是**官方模型、动作损失与配方的RAW/FSDP2适配**，不是原封不动运行官方JAX训练脚本。必要差异：

- RAW精确帧读取替代LeRobot RGB loader，训练源全帧均匀采样，不沿用视觉预训练的stride5 anchors。外部相机95%裁剪/±5°几何增强，腕相机不增强；不做RGB色彩抖动或翻转。
- 双卡FSDP2组织官方联合语言/动作层；FP32主权重及Adam、BF16计算/FP32归约，EMA分片放CPU。SDPA替代显式attention矩阵。
- 删除全mask的第三相机槽、在CPU裁掉右侧语言padding；保留有效token位置与attention mask语义。官方LIBERO的discrete_state_input=False设置保留。
- 逐帧pread/fadvise、reader LRU12/小标签LRU16、每rank worker2/prefetch1/CPU线程8，不加载完整轨迹或建立全量图像缓存。

## 环境与验证

隔离环境 `/root/owac/runtime-j5-pi05` 继承服务器Torch2.12.1+cu132，依赖见 `configs/backends/j5-pi05-runtime/requirements.txt`。transformers4.57.0装官方replacement；仅兼容其LossKwargs类型别名和安装版本检测，补丁已保存。初次官方base转换被旧版本检测拦下，日志保留；兼容后用官方converter成功生成 `/root/owac/pi05-base-pytorch/model.safetensors`。

针对性证据位于本地/远端 `outputs/j5-pi05-full-20261030/`：

- 官方小模型联合层前向/梯度对照通过：输出最大差4.77e-7，输入梯度最大差1.97e-6。
- 真实完整策略FP32检查：删除padding后loss元素最大差7.15e-6；分布式验证用联合前向采样与官方KV-cache采样最大差1.55e-6、relative L2 1.54e-6。BF16对应采样relative L2约1.23%，不宣称bit-exact。
- 双卡真实2步更新/native0保存；完整模型/Adam/EMA/两rank RNG恢复后推进到15并再次native0保存。CPU合并导出EMA策略成功。
- RAW策略与官方RGB策略各完成一次真实LIBERO初态的5步闭环连通检查/native0，保存视频和动作。这是工程检查，**不是任务成功率验证**。RGB侧发现并修复官方resize单样本batch丢维及观察对象缺少可选token字段的问题，失败日志独立保留。
- 两项动作数据测试通过；新增实现ruff通过。全库 `make check` 仍被既有213项lint错误阻断，日志保留，没有改动无关文件来掩盖结果。

## 内存事件与修复

首次并行恢复完整检查点时，文件缓存与CPU拷贝叠加，step3总内存到114.04GiB，接近116GiB容器上限；OOM计数为0。释放本次工程checkpoint的文件页后，step10总内存38.78GiB。不能把这次事件省略或宣称始终没有内存压力。

在15步完整保存停止后，改为逐rank、逐组件恢复/保存；已复制的checkpoint文件局部fadvise释放，Adam CPU小计数器clone后不再持有整份mmap。只管理本实验文件，不做系统全局drop_caches。SwanLab分别记录总内存、匿名内存、文件缓存与共享内存。

新增EMA验证在177源flow和五例采样均完成后，暴露FSDP根模块在无反向的eval后仍持有完整权重的问题，切回分片online权重时报shape mismatch/native1；失败日志、源码及退出收据保留于 `attempts/eval-reshard-15`，没有丢弃15步检查点。修复为恢复online权重前显式root reshard；随后从15完整恢复，重新完成同一验证/采样并继续训练，16步完整检查点已经写出。

修复后的240个每秒监测样本覆盖恢复、EMA验证、实际更新和保存：总内存峰值 **76.83GiB**；OOM=0、memory.max事件没有新增。step16为13.88秒/update、18.44帧/秒，总RAM56.00GiB，其中匿名20.92GiB、文件缓存34.10GiB。证据 `memory-resume-monitor.jsonl`。这是当前监测窗口结论，不代替之后数天运行的持续观测。

micro4未压缩padding时24.17秒/update；micro8压缩无效槽后step10为13.59秒/update、18.83帧/秒，allocated峰值25.58GiB/rank。按该短窗外推30k约113小时，实际含评估/保存会更久，不作为保证。

修复后继续至step20：13.48秒/update、18.99帧/秒、总RAM56.04GiB。30秒稳态采样双GPU平均利用率77.9%/73.1%，nvidia-smi峰值29392MiB/卡（该值包含CUDA保留内存，不能与allocated25.58GiB混为一谈）；没有用瞬时100%代替平均值。

## 训练、评估和产物

配置：`configs/experiments/j5_pi05_full.json`；远端输出：`/root/owac/repo/outputs/j5-pi05-full-20261030/`；执行源码快照：该目录 `source/src`。检查点为每rank model/optimizer/EMA/RNG加metadata，保留可恢复的latest。SIGUSR1只在完整优化器更新边界保存并正常退出，没有失败自动重启。

[SwanLab训练](https://swanlab.cn/@Jeong/OWAC/runs/owac-j5-pi05-full-20261030)。每500步评估固定177验证源的完整32维/真实7维flow loss、按照明分项；每2000步记录实际采样动作误差和gripper符号一致率。恢复时额外跑177源flow以及每光照一例的5样本采样探针，不把探针当作完整动作质量评价。

30k正常结束后，launcher自动导出完整EMA策略，进入双GPU闭环：40个LIBERO任务×5种照明×5个官方初态，RAW和官方RGB各1000回合。初态、照明参数、传感器噪声种子与flow noise规则对齐；RGB对照由同一noised RAW10经默认ISP得到。保留逐回合native success、视频、动作轨迹、配置，另建SwanLab评估run `owac-j5-pi05-eval-20261030`。完成后写 `closed-loop/comparison.json` 和 `evaluation.exit.json`；故障保留原始退出，不重试改种子。

这是RAW策略与已发布RGB策略的系统级比较。官方RGB策略训练分布与本轮五照明训练不同；若要把收益严格归因于J5视觉预训练，仍需同数据、同训练预算的视觉初始化消融。当前连通检查、吞吐和下降的训练loss都不能替代闭环成功率结论。
